Journey · First campaign

First email campaign

Who: new person. Never sent a campaign here. May be alone or with an assistant (human or AI agent via a connect link).

Build-story fuel. Each step names the screen, what is on it, the buttons, and what the user does.

Goal

Goal

Connect mailbox → get people → write/send first email → see a reply (or a test) in the inbox.

Path A

Path A — I have a list

Given / When / Then. Numbered. Plain.

1 · land

Story

I land on the product and start a campaign.

I do: Choose Start free (or open Campaigns if I am already in).

I see: Empty Campaigns. Primary control to begin.

On screen — Campaigns (empty)

  • Things: Empty state copy. No campaign rows. Side nav with Campaigns, Inbox, People (or Contacts).
  • Buttons: New campaign (primary). Optional: Start free on the landing before login.
  • User doing: Opens the empty Campaigns list and starts a blank campaign.

Build note: Empty campaigns screen + New campaign CTA → opens campaign edit shell.

2 · mailbox

Story

I connect Google or SMTP so mail leaves from my mailbox.

I do: Click Connect Gmail (or Connect SMTP) and finish the provider flow.

I see: Mailbox connected. Address shown as the from-account.

On screen — Connect mailbox

  • Things: From / mailbox panel. Status: not connected. Fields for SMTP host, port, user, password (if SMTP path). Gmail OAuth sheet when Google is chosen.
  • Buttons: Connect Gmail · Connect SMTP · Save / Done after success.
  • User doing: Links their mailbox so sends go out as them.

Build note: Connect-mailbox modal or settings panel; OAuth + SMTP form; store connected account on campaign/workspace.

3 · people

Story

I upload a CSV. People appear on the campaign.

I do: Click Upload CSV, pick a file, confirm the column map.

I see: Contact rows on the campaign (name, email, merge fields).

On screen — CSV upload (on campaign)

  • Things: People panel / list on the campaign. Drop zone or file picker. Column map (email, firstName, …). Preview of first rows. Count of people added.
  • Buttons: Upload CSV · Add contact · Map columns / Confirm · Cancel.
  • User doing: Loads their list onto this campaign.

Build note: CSV uploader + column map + people table bound to campaign audience.

4 · write

Story

I write the email (Hi {{firstName}}…) and preview one person.

I do: Type subject and body. Insert merge fields. Open preview for one row.

I see: Draft with tokens. Preview shows a real first name from the list.

On screen — Campaign edit (people + message)

  • Things: People list (left or top). Message panel: Subject field, Body editor. Merge-field chips ({{firstName}}, {{email}}). Preview pane for one selected person. From = connected mailbox.
  • Buttons: Insert field · Preview · Send test · Send (may stay disabled until ready).
  • User doing: Writes the first message and checks how it looks for one person.

Build note: Campaign edit layout — people list + composer + merge + single-row preview.

5 · test

Story

I send a test to myself. I see it in Inbox.

I do: Click Send test. Confirm my address. Open Inbox.

I see: Test message in Inbox (or confirmation that it left). Thread on me / the test contact.

On screen — Preview / test

  • Things: Test-to field (defaults to my email). Preview of rendered subject/body. Status toast: test sent.
  • Buttons: Send test · Open Inbox · Back to edit.
  • User doing: Proves the send path with one message to themselves before the list goes out.

Build note: Send-test action → delivery + Inbox row for the test recipient.

6 · send

Story

I send to the list. Mail leaves from my mailbox.

I do: Click Send. Confirm the count. Watch status move to sending / sent.

I see: Campaign status: sending then sent. From address = my mailbox.

On screen — Sending

  • Things: Confirm sheet: N people, from address, subject. Progress or status on the campaign row. People list with per-row send state (queued / sent / failed).
  • Buttons: Send · Confirm send · Cancel. Later: Pause if we support it (not required for first journey).
  • User doing: Approves the real send to the uploaded list.

Build note: Confirm-send dialog + campaign status + per-contact send state.

7 · reply

Story

Someone replies. The reply sits on that contact in Inbox.

I do: Open Inbox. Select the contact. Read and Reply.

I see: Thread on that person. Reply box ready.

On screen — Inbox thread

  • Things: Inbox list (unread / all). Contact header. Thread of outbound + reply. Reply composer. Link back to the campaign optional.
  • Buttons: Reply · Send (on reply) · open contact.
  • User doing: Answers the first real reply without leaving the book.

Build note: Inbox list + contact thread + reply send tied to mailbox sync.

Path B

Path B — I write the email first

Same screens. Different order. Product stops send until people exist.

B1 · open

Story

I open a campaign and write the message before I have people.

I do: New campaign → type subject and body.

I see: Message panel filled. People panel empty.

On screen — Campaign edit (message first)

  • Things: Empty people list / “No people yet”. Subject + body fields. Merge chips greyed or still insertable.
  • Buttons: Upload CSV · Add contact · Send test / Send (blocked or explains why).
  • User doing: Drafts copy first, then looks for where people go.

Build note: Campaign edit allows empty audience; composer works without rows.

B2 · block

Story

I try to send. Product stops me: need people.

I do: Click Send or Send test without a list.

I see: Clear stop: add people first. Pointer to Upload CSV or Add contact.

On screen — Send blocked

  • Things: Inline error or modal: “Add people before you send.” Empty people panel highlighted.
  • Buttons: Upload CSV · Add contact · Dismiss.
  • User doing: Learns they must load people before the send goes out.

Build note: Guard on Send / Send test when audience count = 0; CTA into upload/add.

B3 · people then send

Story

I upload CSV or add contacts. Then I send or test. Then I use Inbox.

I do: Upload CSV (or Add contact) → Send test / Send → open Inbox.

I see: People on the campaign. Send enabled. Test or replies in Inbox.

On screen — same as Path A steps 3, 5–7

  • Things: CSV upload / add-contact form. Confirm send. Inbox thread.
  • Buttons: Upload CSV · Add contact · Send test · Send · Reply.
  • User doing: Finishes the missing people step, then completes the first send.

Build note: Reuse Path A people + sending + inbox; no separate B-only screens.

Path C

Path C — An agent helps the first time

Share a connect link so an assistant can help. Human still clicks Send (or approves).

C1 · share

Story

I share a connect link so an assistant can help.

I do: Open share / connect. Copy the link. Send it to the assistant.

I see: Connect link + short “what they can do” list. Copy confirmation.

On screen — Share connect link

  • Things: Connect link field. Scope list (mailbox with approval, upload list, draft email, queue send). Expiry or revoke note if we have it.
  • Buttons: Copy link · Revoke · Done.
  • User doing: Gives an assistant limited access to prepare the first campaign.

Build note: Share/connect screen — link generation + scopes + copy.

C2 · agent prepares

Story

The agent prepares the campaign (mailbox with my approval, list, draft, queue).

I do: Approve mailbox connect when asked. Otherwise wait while the agent uploads and drafts.

I see: Campaign filling in: mailbox pending/connected, people count, draft text. Queue ready — not sent.

On screen — Campaign edit (agent-prepared)

  • Things: Same campaign edit: people list, message, from mailbox. Banner: “Prepared by assistant — review before send.” Approval prompt for mailbox if needed.
  • Buttons: Approve mailbox · Review · Send (human). Agent never owns the final Send click.
  • User doing: Watches the prep, approves mailbox if asked, keeps Send for themselves.

Build note: Agent can fill audience + draft + queue; mailbox connect needs human approval; Send gated to human.

C3 · human sends

Story

I review and send. Then I see Inbox.

I do: Read the draft and people. Click Send (or Approve). Open Inbox for replies/tests.

I see: Confirm count. Sent status. Later: replies on contacts in Inbox.

On screen — Review + send + Inbox

  • Things: Review summary (N people, subject, from). Confirm sheet. Then Inbox thread as in Path A.
  • Buttons: Send / Approve send · Edit · Reply in Inbox.
  • User doing: Makes the final send decision and handles replies.

Build note: Human-gated Send on agent-queued campaign; Inbox unchanged from Path A.
